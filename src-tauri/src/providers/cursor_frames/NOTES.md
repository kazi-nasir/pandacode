# Cursor CLI recordings

Recorded 2026-11-02 with Cursor CLI `2026.09.15-d2fe57e` on native Windows 11, signed in, launched as `versions\<v>\node.exe versions\<v>\index.js …` (no shell) with `NO_OPEN_BROWSER=1`, in an empty temporary workspace. The driver sent PandaCode's own `initialize` (`clientCapabilities: {}`, `clientInfo` `pandacode` `0.1.0`).

Each `.jsonl` file is one process: a first `{"args":…}` line, then one entry per event with `t` (ms since spawn), `dir` (`out` = PandaCode to CLI, `in` = CLI frame, `stderr`, `exit`, `timeout`) and the frame.

Scrubbing: workspace path → `<workspace>`, home → `<home>`, user and machine names → `<user>`, emails → `<email>`, session id → `11111111-1111-4111-8111-111111111111`, tool-call UUIDs → `uuid-N`. Long lists are trimmed and say so in a `_trimmed` field (`availableModels` and the model config option to 5 entries; `availableCommands` to 2 built-in entries, dropping the user's own skills). Nothing else is changed.

One chat was created (the session in `session.jsonl`, reopened in `resume.jsonl`). The follow-up recordings, including `plan-deny.jsonl`, load that same chat with `session/load` and do not call `session/new`. The CLI has no command to delete a chat (`flags.md`), so it remains in the account.

Gap recordings (2026-11-03, same CLI version, driver `recording/record-gaps.mjs`, same scrub rules plus: isolated profile directories → `<profile>`, any login/auth URL → `<login-url>`, the second session id → `22222222-2222-4222-8222-222222222222`, `session/list` titles → `<title>`). The signed-out files ran in fresh empty temporary profiles (`HOME`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `XDG_CONFIG_HOME` pointed at new temp directories, every `CURSOR_*` variable removed, `NO_OPEN_BROWSER=1`); the user's real profile was not read for credentials, nothing logged out, and no session request was sent. `model-unknown-load.jsonl` and `question-agent.jsonl` use the existing chat. `model-new.jsonl` is the one deliberate `session/new` (no prompt sent): `--model` on `session/new` can only be shown on `session/new`. It created a second chat (listed by `session/list` in that file), which stays in the account.
